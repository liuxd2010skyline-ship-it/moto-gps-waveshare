## 3. 建筑细节与道路渐变：找回的原要求

### 建筑

来源：[BUILDING_MATERIAL_V3.md](BUILDING_MATERIAL_V3.md)。材质参考：[建筑 V3 整屏效果](building-material-v3-screen-effect.png)。

1. 依据**真实多边形轮廓**绘制；保留各栋建筑的空隙、不规则边界、尺度差异与街区疏密。不能变成规律方块阵列。
2. 普通建筑以哑光深石墨灰 `#303335` 为基准；相邻建筑允许在 `#2B2F31…#373B3D` 内低幅变化，不制造网格、粗噪点、浮雕或伪三维高度。
3. 不加亮色独立描边。轮廓与近黑空隙完成分隔；抗锯齿边缘干净，视觉厚度不超过约 1 个实际像素。
4. 保持 **背景 < 建筑 < 灰色道路 < 象牙白路线/主要信息**的明度层次。建筑有细节，但不抢路线。
5. 不给每栋建筑加明显渐变、投影或光晕。建筑与道路整体在下部短距离融入黑色信息区。
6. 没有建筑数据时，不补造装饰矩形、随机街区、镜像轮廓或地标。绿地、水域暂维持近黑体系，不凭空推断用地。

V3 整屏图原文仍标为视觉候选；其材质方向随后成为工程默认。它有旧版尾部/文字细节，**仅用于建筑材质对照，不能覆盖最新无尾巴与英文规则**。

### 道路及其微弱明暗过渡

来源：[ROAD_AND_VEHICLE_V1.md](ROAD_AND_VEHICLE_V1.md)、[建筑 V3 第 5 条](BUILDING_MATERIAL_V3.md)、[原生尺寸确认稿](NAV_DRAWING_STANDARD_CONFIRMATION.md)。观感参考：[道路与位置箭头整屏效果](road-and-position-marker-v1-screen-effect.png)。

| 道路层级 | 466 px 线宽 | 当前核心色 |
| --- | ---: | --- |
| 主路 | 约 5.2 px | `#62696D` |
| 普通道路 | 约 3.9 px | `#42474B` |
| 支路 | 约 2.6 px | `#2B3033` |

- **道路横向/上下应有极细微灰阶过渡**，不能整层一直用死板平色；银灰变化要克制，不做霓虹、金属浮雕或强高光。
- 连续道路采用圆润端点和连接；独立道路不得为填屏而强行连起来。
- 旧道路稿还提出主路 10 px、普通道路 6.4 px 的暗路肩；它与导航路线的 18 px 下衬属于不同层。
- 桥隧、上下层和交叉关系必须由真实层级数据决定，不能从视觉效果图推断。
- `BUILDING_COLOR_V1.md` 曾建议约 6–9 个 RGB 等级的上下差异，但该整稿被后续视觉迭代替代；这个幅度**没有单独冻结为最终参数**。当前已找回的确定方向是“细微过渡”，其强度仍需 466 px 对照验收。
- [实现审计](NAV_IMPLEMENTATION_AUDIT_2026-10-06.md)明确记录：分级线宽/颜色已有，**材质微渐变未完成，固件主要仍为平色**。你指出的道路渐变缺失符合记录。

## 5. 柔光、运动、电脑调节：原方案完整规则

来源：[代码化设计契约第 5 节](NAV_CODE_READY_SYSTEM_V1.md)、[电脑环境光实验台](nav-ambient-motion-demo.html)、[行为参考源码](nav-code-ready-v1.js)、[唯一色板](../shared/nav_ui/assets/nav_design_palette.json)。

### 视觉与融合

- 使用原本喜欢的 **Soft Graphite 不规则微漫反射**，只增加适量存在感；不采用后来被否决的大聚光、蓝/青多色或明显同心色带。
- 非地理底材位于真实建筑和道路下面；仅路线、道路、有限地物和完整数据都共用同一层和时间。
- 柔光有宽范围过渡与局部亮部，但不挤为同一中心；主体路线、箭头、地图坐标和文字不跟着漂移。
- 色板：基底 `#263338`、中间层 `#11191C`；三类软光 `#35474C / #3C4D52 / #34464A`；中间色 `#2E3E42 / #344248`。模板中心 alpha `.29 / .26 / .21`。

### 随机生命周期与事件

| 项目 | 既有规则 |
| --- | --- |
| 同时数量 | 可变化、最多 4 组；不是固定三组 |
| 形体 | 每组两个叠合椭圆；出生中心间距至少 68 px；总 opacity 预算 ≤1.9 |
| 出生 | 每 4.5–8.5 逻辑秒尝试一次；达到上限或找不到合适间距时跳过 |
| 寿命 | 14–26 逻辑秒，清理过期记录，不累积无限历史 |
| 渐入/渐出 | 2.8–4.2 s / 3.8–5.8 s，使用 smoothstep，从透明出现并回到透明 |
| 漂移 | 出生时随机确定参数，连续运动；Ax12–20、Ay8–14、Tx5–9、Ty7–12，叠加缓慢分量；不是每帧重新抽样 |
| 时间倍率 | `speed==0 ? 0 : 0.3+0.014*speed`；幅度乘 `travel/65` |
| 关键事件 | 路线版本、下一动作身份改变，或首次跨过 200/80/30 m 才触发一次约 1.1 s 的弱反馈；opacity 最多 +.03 |
| 抑制重复 | 距离包更新、阈值附近抖动、地物到达不重复触发、不重置动画 |
| 失效/减少动态 | GPS 失效、断连、重算、待命或减少动态时稳定停留；文字独立表达状态 |
| 刷新预算 | 浏览器参考 125 ms；硬件集成目标 2 Hz，性能不足时降到 1 Hz 或静止，优先保障导航 |
| 色阶 | 同一色板、固定 8×8 空间抖动；不每帧随机抖动，不为柔光新增每帧整屏 RGB565 缓冲 |

### 电脑控制与演示

- 存在感、速度、幅度：三个 **0–100 滑杆**，当前电脑实验台默认 `62/75/85`，保存在浏览器本地。
- 暂停、减少动态、加速观察、模拟下一指引变化，以及四种地物密度切换。
- [1× 真彩动画 PNG](nav-ambient-lab-1x.png)：录制 16 秒；算法本身不按 16 秒固定重复。
- [GIF](nav-ambient-lab-1x.gif) 仅便于观察动作；256 色不适合判断暗部渐变。
- [完整/最坏数据融合对照](nav-ambient-lab-fusion-comparison.png) 是合成测试：完整样例 100 栋，不代表实际北京数据或设备一次传输容量。

这些调节已存在于**电脑预览**；此前用户明确先做电脑调节。当前硬件设置页中的电量/亮度不等于这三个外观滑杆，固件中的色板 token 也不等于柔光生命周期已经移植。

### 判定所需六类事实

1. BLE 连接及导航数据新鲜度；互联网状态独立。
2. 定位新鲜度、精度、连续性与道路可区分程度。
3. 速度和连续航向稳定性。
4. 路线 ID/generation、动作身份、几何与可信位置的匹配。
5. 道路、建筑、地表各自的真实覆盖和数据修订。
6. 限速对应路段与有效期。

最新浏览器选择器优先级：**手机离线/连接中 → 到达 → 未设置目的地 → 偏航/重算 → GPS 失效 → 等待有效引导 → 仅动作（几何未到）→ 仅路线 → 有道路 → 完整地物**。

引导有效性要同时满足：导航中、有目的地、有新鲜可信定位、动作和距离可用、不在偏航/重算。路线几何另需匹配 ID/generation、2–24 个有效点、首点靠近当前位置锚点；地图数量不能证明引导有效。

一份快照一次决定路线、位置、HUD、限速和状态的可见性，不能先画旧路线再单独隐藏数字。连续证据、进入/退出滞后等已有规划，但复杂情况的秒数/米数未全部实测校准。核心已有约 5 s stale 与 50 m 精度政策，也不能等同于 18 种情境算法全已落地。

| 柔光及色阶 | 浏览器生命周期、事件与 RGB565 模拟；硬件已有统一色板 token | 没有完整硬件 mask、计时/生命周期模块、固定抖动输出 |
| 场景算法 | 核心已有部分定位新鲜度、偏航/重算、连接与版本逻辑；浏览器有选择器 | 统一显示有效性契约、18 情境完整联动、复杂触发阈值仍缺 |
