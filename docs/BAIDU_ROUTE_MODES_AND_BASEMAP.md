# 百度双路线模式与圆屏底图方案

## 用户目标

- iPhone 原生 App 使用百度地图服务，在中国大陆规划路线，不依赖常驻网关。
- “机动车”先采用**驾车、避高速**路线供摩托车骑行者参考；它不等于摩托车专用路线，也不保证避开摩托车禁行道路。
- “非机动车”提供**普通自行车**和**电动自行车**两种百度骑行规划。
- 手机行前路线预览沿用上一版的路线示意图；不在 iPhone 上复刻微雪风格底图。微雪 ESP32-S3-Touch-AMOLED-1.75C 保留现有 LVGL 导航 UI、路线、路口、速度和方向绘图。圆屏道路底图仍须来自真实地图数据，不能用随机线或把路线本身充当周边道路。

## 数据链路

```text
用户选终点、模式 → 百度 iOS 地图 SDK → 路线点/距离/时间/分步指令
                  → iPhone 导航核心 → BLE 路线几何和导航快照
                  → 微雪 LVGL 当前绘图层（路线、箭头、文字）

经授权的周边地图源 → iPhone 裁剪、简化 500 m 窗口 → BLE MapScene 0x14
                  → 微雪 LVGL 当前道路/建筑绘图层
```

百度 Map SDK 的驾车与骑行接口都返回路线本身，不返回导航区域内所有道路的可重绘线几何。因此，**完成双路线模式不等于完成圆屏底图**。

## 圆屏底图的两个可实施方向

1. **取得可在外接圆屏使用的中国地图道路矢量数据许可。** iPhone 将当前位置周边的道路、建筑裁剪成现有 `MapScene`。这条路线完全沿用微雪现有绘图与 BLE 协议；关键是确认数据提供方允许二次展示、设备使用、临时缓存以及实际覆盖范围。不能把百度地图内部瓦片拆解为道路数据。
2. **使用百度官方地图截图能力，传输图像作底层。** 普通地图有 `BMKMapView.takeSnapshot`；百度另有步骑行后台投屏用的 `BMKBackgroundMapView`。微雪现有路线、指示和文字仍由 LVGL 绘制，但需要新增分片图像协议、缓存与图像层；原有 `MapScene 0x14` 是矢量道路协议，不能直接塞图片。必须先确认当前个人 AK、外接车载圆屏和图像传输场景的使用许可。现有免费配额不代表车载投屏自动获准。

现阶段先真机验证百度驾车、自行车和电动自行车路线以及手机路线示意图；圆屏保留路线绘图。圆屏真实底图必须在确认授权数据源后接入，不能把济南示例、网格或路线替代全国底图。

手机预览用上一版的 SwiftUI `Canvas` 绘制路线示意，不调用百度地图底图视图，也不使用微雪端的配色或图层。百度仍提供地点搜索和路线几何。`shared/nav_ui/include/moto_map_visual_style.h` 与 LVGL 绘制流程只服务圆屏；本次恢复手机预览时没有改动固件、共享绘图代码或 BLE 地图协议。手机没有把百度瓦片解析成 `MapScene`，也没有把截图发给圆屏。

## 地物类别与圆屏填色

用户期望的地图不是仅将路线画在照片或网格上，而是按真实地物类别绘制：道路为分级折线，建筑为闭合面，草地或公园为绿色面，水体为蓝色面，再把导航路线和箭头画在最上层。每个面至少需要类别、边界点、坐标系和来源；仅知道某点附近有“公园”或“建筑”这个 POI 名称，不足以绘制该区域的形状。

当前 `MapScene (0x14)` 只携带道路折线与建筑轮廓；固件用 LVGL 画出线条，并在地图下缘渐隐以衔接导航信息。建筑尚未填色，也没有草地、水体字段。手机里的百度地图 SDK 自己按类别渲染底图，但常规地图与路线接口不会把整片街区的所有地物轮廓交给 App。因此，百度个性化样式 ID 能改变**手机上百度底图的地物颜色**，不能凭这个 ID 为微雪圆屏导出同样的矢量面。

下一阶段须先确认合法且覆盖目标城市的面要素数据源，再扩展 `MapScene` 的类别、面边界和 BLE 分片预算，最后在 LVGL 中按“绿地/水体 → 建筑 → 道路 → 路线”顺序绘制。样式表应独立于数据，允许以后只改颜色、线宽与显隐而不重做地图获取。不能根据 POI 位置推测实际建筑或草地边界。

## 验收顺序

1. 同一终点分别选驾车参考、自行车、电动自行车；记录路线、距离、时间与转向提示确实按所选模式变化。
2. 出现偏航后重算仍保持原模式；无骑行路况时不显示驾车路况说明。
3. 手机行前预览显示所选百度路线的示意线条；切换路线与出行方式时线条随之变化。此示意图不表示周边道路。
4. 接入经许可的圆屏底图后，在同一坐标系中对齐灰色道路与高亮路线；离开内置济南区域实测，不得仍显示样例道路。
5. 验证锁屏、断网、蓝牙重连与实际骑行时的刷新、耗电和显示可读性。
