# 已知问题与发布边界

本次公开的是 Waveshare 成品验证线的开发快照，不是验证通过的量产版本。
当前 iPhone 分支已改为百度 iOS SDK 直连，无需高德网关；以下涉及高德网关的记录是旧版本历史问题。第三阶段当前范围见[执行方案](PHASE3_EXECUTION_PLAN.md)与[海淀区底图核查](BEIJING_HAIDIAN_MAP_SOURCE_REVIEW.md)。

| 状态 | 问题 | 目前结论 |
| --- | --- | --- |
| 未关闭 | 离家后圆屏停留 `WAITING FOR PHONE` | BLE / iOS 后台状态恢复需继续定位；不是已经证明为手机没网。当前版本不保证锁屏长期保活 |
| 历史记录，待新路线回归 | 旧版临沂前往济南西站没有可选路线 | 原路径依赖高德网关；现用百度 iOS SDK，需在新路径分别验证驾车、自行车、电动自行车，不沿用旧网关故障结论 |
| 待回归 | 真机路线与 App 预览不一致、出现绕路 | 路线选择传递已有逻辑与自动测试，但尚未完成对应跨城实车回归 |
| 待回归 | 快速转向时翻页/撕裂感 | 已有双缓冲、插值和 CO5300 TE 同步逻辑；实际流畅度、持续帧率与耗电仍需测量 |
| 固有边界 | 静止时绝对北向 | QMI8658 只有加速度计和陀螺仪，没有磁力计。手机在包里时不能把手机机身朝向当作车头方向 |
| 固有边界 | 济南之外背景路网 | 内置 OSM 数据只供济南演示；真实百度导航不发送这套数据。海淀圆屏底图尚缺合规的真实地物数据源，不代表路线 API 不支持该城市 |
| 固有边界 | 限速、建筑缺失 | 依赖真实数据覆盖，不补画虚构内容；路线服务不总是给出可信法定限速 |
| 未验收 | 电池续航、USB/电池组合关机、防水、抗振、骑行安全 | 成品开发板并非本项目认证的车规设备 |

本机演示用公共 POI 附近的真实 OSM 几何，可检查画面和动作关系，但不能验收实时路况、
真实定位精度、后台 BLE、手机蜂窝网络切换或真实导航正确性。

调试 BLE 时先停车：确认 App 前台是否恢复、iOS 蓝牙/定位权限、圆屏连接状态、
协议握手是否完成，再核对手机内百度 AK 与侧载后实际 Bundle ID 以及路线请求错误信息。不要用重启“偶尔成功”代替根因记录。
提交日志前删掉经纬度、设备 UUID、序列号、服务令牌等个人信息。
