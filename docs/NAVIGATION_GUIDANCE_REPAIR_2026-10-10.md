# 实测导航问题：数据链路与修正

日期：2026-10-10。基线：8a871345（静态版），App 0.4.0(7)。修正版 App 构建号为 8，需要与同次固件配套验证。

## 原有逻辑

1. iPhone Core Location 提供 WGS84 位置、精度、速度和 GPS course。没有开启手机磁力计 heading。
2. 位置转换一次到 GCJ-02，与百度路线及北京离线底图统一。NavCore 把定位投影到路线线段，计算路线进度；进度只增不减。
3. 几何累计长度按提供方的全程距离等比例映射；下一指引距离为事件位置减当前进度，ETA 按剩余距离比例估算，并非完整的百度实时导航引擎。
4. 百度 SDK 的每个 step 起点累计距离，曾直接被用作整段 instruction 的转向位置。只有少数文字关键字被识别；默认是直行。遇到“沿路行驶 100 米后右转”，动作可能挂到路段起点并过早被消耗。
5. NavCore 曾选择第一个尚未过去的步骤，包括直行，所以其后真实转向可能被遮住。没有使用真实几何来补齐未识别的转向。
6. 圆屏另将手机 course 与 QMI8658 陀螺仪融合。GPS 低速保护阈值 0.5m/s，硬件融合 GPS 锚定阈值 1.5m/s；两端口径不同。陀螺仪 125Hz 采样会更新地图，混入仪表自身转动、漂移等因素。
7. 原偏航条件为距路线超过 45m、累计 3 次；请求失败后等 5 秒再试。GPS 更新频率由 iOS 决定；1 秒状态轮询、200ms 蓝牙发送合并，以及绘制耗时是不同环节。

固定的把手安装偏角本身不应使 GPS course 恒定偏右；这里不能仅凭现象断言具体传感器故障。原融合存在影响路径，需要通过取消它以及实测来验证。

## 本次修正

- 百度适配层保留每一步在完整折线中的起止顶点索引。将“行驶多少米后转弯”和“先转弯再行驶”分别关联到出口和入口，再以对应几何拐点校验。
- HTML 标记、右拐/左拐、偏左/偏右等文字一并规范化。SDK 步骤边界的真实几何转向可补全缺失文字；不会将路段内部所有弯曲都编造成路口动作。
- 直行步骤不再挡住下一处实际动作。到达路口保留 4–10m 精度相关的通过余量，减少轻微漂移使图标提前跳走。
- 不再启动 QMI8658 航向任务；硬件按手机已计算的方向显示。保留旧回调为空操作，确保旧调用也无法重新引入转动或重绘。
- 行驶时优先当前匹配路段的方向，非整段前方路线的平均方向。高可信 GPS course 与路线方向差超过 60° 时不强行吸附；停下后保持地图。首次静止启动可根据所在路线定向。
- 手机仅接纳 courseAccuracy 0–30° 的 course；速度低于 1.5m/s 时不把 course 当强参考，可用真实位移和路段方向。移动方向独立于手机、仪表的物理安装角度。
- 原“指南针”页明确显示 TRAVEL COURSE；停车或定位失效时显示 MOVE TO UPDATE 与 `---`，不冒充独立磁罗盘。导航地图仍保持上次方向。
- 偏航需超过 max(30m, 两倍水平定位误差)，2 次定位并持续至少 1 秒。重复时间戳不会增加确认次数；明显偏离路线的定位不能消耗原路线进度和转向。
- 请求失败后的重试间隔降到 2 秒。状态时限轮询 250ms，状态无变化时不重复发送。蓝牙合并窗口降到 100ms。
- 路线匹配用累计距离二分找到有效搜索起点，先检查范围再计算三角函数，避免长路线每次定位扫描所有路段。

这会减少本地判断和发送延迟，不保证百度服务器响应时间，不提高 GPS 本身的采样频率。静态背景/完全关闭方案继续生效。

## 回归用例与实机验收

自动化用例覆盖：一步末端右转、下一步起点重复右转、HTML/同义词、只有直行文字但边界有右转、连续左右转、无指令的内部弯道、无效顶点索引、直行遮挡转向、低速/停车、反向行驶、重复定位、精度差漂移、偏航不消耗路口、仪表转动不改方向也不调度绘图。

编译和自动化结果以本次提交的 GitHub Actions 为准；这些回放用例不能代替实地验证，也未包含本次用户现场的原始 GPS/百度响应。

1. 配套安装 App (8) 和固件，打开已下载的北京离线包。
2. 安全停放时转动仪表或车把：导航地图应保持稳定，方向页提示移动更新。
3. 选择含右转和连续两次转向的短路线，行驶时确认提前显示方向，距离倒数至路口，通过后切换下一动作。
4. 漏过一次转弯后，确认出现重算，且单个漂移点不会反复算路。记录从偏离至新路线出现的时间，区分本地确认与服务器等待。
5. 若仍有漏转，需要该次路线的脱敏步骤文字/折线及定位时间序列，用于复现；不能仅靠再次增加刷新频率解决。
