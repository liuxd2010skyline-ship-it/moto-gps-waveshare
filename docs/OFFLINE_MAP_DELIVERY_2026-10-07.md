# 离线底图与建筑传输：实施记录

## 已确认的方向

2026-10-06 用户同意先用免费的 OpenStreetMap 离线包验证海淀道路和建筑；这项选择取代此前国内提供方限定对本轮验证的阻碍。手机上的百度路线预览和电动车路线保持既有流程。离线地物是独立的地图背景，不替代百度路线规划。

## 数据路径

固定日期的 Geofabrik 北京 OSM PBF → 官方文件校验 → pyosmium 4.2.0 解析真实道路/建筑 → WGS-84 在构建时转换一次为 GCJ-02 → MGPS SQLite/R-tree 本地包 → 按位置选择北京或济南 → 裁剪和完整轮廓筛选 → 按 BLE 能力/MTU 分配预算 → MapScene ACK → 共享 LVGL 画图。

官方源：[北京提取页](https://download.geofabrik.de/asia/china/beijing.html)。固定源文件 `beijing-261004.osm.pbf`，保留来源 URL、PBF SHA-256、源时间、数据库 SHA-256、转换前后点数和覆盖范围。软件生成包不是对整个海淀实地测绘完整性的保证。

### 构建

需要 Node 24 和 Python + pyosmium 4.2.0。在仓库根运行：

```sh
python scripts/offline_map/prepare_beijing_pack.py
```

输出在 `build/offline-maps/`，手机资源是 `beijing-v1.sqlite` 和来源清单。GitHub 的 `Build Beijing offline map` 工作流自动完成构建、数据库检查和同一生产 Swift 查询代码的测试。iPhone 工作流也在 XcodeGen 之前生成相同资源，直接随 App 安装，无常驻服务器。

## 数据和传输改动

- 真实导航、演示导航都从当前位置查询本地包；没有定位或不在地图包范围时不挪用其他城市地物。
- 道路计算与圆形窗口的真实交点，区分离开后重新进入的片段，不在缺口之间补一条连接线。
- 建筑去除重复相邻点/闭合点，保持完整外轮廓；起点旋转、顺逆时针重复形体去重；不截断点列后强行闭合。
- 建筑接收容量统一由 16 栋/128 点扩大到 48 栋/240 点。道路仍为 24 条/192 点。`CapabilityDenseMapScene` bit 8 使新手机面对旧固件时继续发送旧预算。
- 20-byte MTU 下总地物包限制在 768 bytes；较大 MTU 下最多 4096 bytes。单张地图最多 96 分包，15 ms 间隔的理想发出时间约 1.44 s；实际受 CoreBluetooth 背压影响。
- 只在旧队列排空后加入地图，分包期间合并最新导航/媒体状态，避免快照把未完成的地图挤掉。地图 ACK 超时从最后一包写入后开始。
- 重试预算按场景版本记账。失败三次只停止该地图重试，新窗口可继续；不因为地物包失败反复重连整个导航。
- 手机「我的圆屏」显示查询地物数和圆屏 ACK 状态。「圆屏已接收」代表协议接收确认，不代表已完成实地视觉验收。

## 验证与边界

测试覆盖：两端在窗口外的长路、出入窗口的分段、逆向道路/旋转建筑去重、48 栋完整轮廓、旧固件预算、20-byte MTU 下两种图层都有保留、济南包不得出现在海淀、ACK 延迟/迟到/重复和新版本重试。云端数据检查要求中关村、五道口、上地周边确有真实道路和建筑；测试不使用设计用的合成街区冒充海淀。

本轮保留建筑外轮廓，尚不传建筑内孔；OSM 未收录地物不能补造。桥隧层级、逐区域完整覆盖、新鲜度等语义仍需扩展。室外路线与建筑位置对齐、锁屏蓝牙和圆屏实际容量/性能需要更新两端后验收。

本轮优先完成数据基础。V6/B 的柔光生命周期、RGB565 抖动材质、细微道路/建筑渐变、窄边缘、英文 HUD 和统一失效场景仍按设计审计逐项进入固件，不能把浏览器预览算作已烧录实现。
