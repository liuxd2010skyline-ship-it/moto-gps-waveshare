## 原作者机制优先的实施决定

目标效果是原作者圆屏上的真实周边道路、建筑与高亮路线；原理固定为「手机取得并整理地图几何 → BLE 发送局部 `MapScene` → ESP32/LVGL 自行绘制」。不以传输地图截图、屏幕镜像或重做手机预览替代这条主链。已核对当前分支与原作者上游：`platforms/esp32`、`shared/ble_protocol`、`shared/nav_core`、`shared/offline_map` 的目录树完全相同；`shared/nav_ui` 仅抽取同值样式常量并加入下缘渐变，几何与 BLE 绘图流程沿用。

创新点是手机侧的可替换「局部场景编译器」：国内获准使用的数据接口只提供真实道路、建筑、绿地、水域几何；编译器统一坐标、按视野裁剪、按屏幕分辨率简化、按 BLE 容量排序，并附来源及时效元数据。先用现有 `MapScene 0x14` 打通道路与建筑；地物填色才使用兼容的新版本。路线与转向消息优先发送，周边场景低频更新，弱网时只能沿用许可允许的缓存或明确标记无底图。

原作者的路线来源为高德网关、底图来源为 OSM/Protomaps，二者不是同一数据链。当前百度 iOS SDK 已替换路线来源，但按「仅中国数据提供方、无常驻网关」要求，真实导航不能继续混入 OSM 济南演示地图。官方国内地方节点确有数据 API 或要素服务，但是否返回足够细的道路/建筑/绿地/水域边界、是否允许圆屏重绘及临时缓存，须以具体接口样本和许可确认；不把页面名称「矢量地图」当作已取得原始几何。

## 已锁定的产品决定

- 硬件仍为 Waveshare ESP32-S3-Touch-AMOLED-1.75C；使用现有 LVGL 圆盘布局、色彩、导航图标、路线层及上下渐变。仅为真实地物增加必要的绘图层，不重做界面。
- iPhone 仍负责百度地点搜索、驾车避高速参考路线、自行车及电动自行车路线、定位和导航状态；行前路线预览保留第二阶段已测试版本。驾车路线不宣称摩托车专用或自动规避禁行。
- iPhone 到圆屏仍走 BLE。百度导航路线与周边底图是两条独立数据链：路线只提供高亮线和导航信息；道路、建筑、绿地、水体须有各自真实几何来源。
- 不增加常驻网关，不依赖安卓，也不把济南演示数据当作真实行驶区域的地图。地图样式参数与地图数据分离，后续改色彩和线宽无需更换数据源。
- 长期免费、仅使用中国地图数据提供方、外接圆屏显示，是数据源选择的硬条件；不能凭“API 有免费额度”推断再绘制、缓存和车载使用已获许可。

## 必须先过的两道门槛

**A. 使用范围。** 向百度确认当前 iOS AK 的路线结果、导航提示在这块摩托车圆屏上显示是否属于其允许的个人 DIY/外接显示使用范围，以及驾车和步骑行是否有不同要求。百度现行服务条款对车载场景规定另行协商书面授权，并限制提取、修改、缓存或单独展示地图数据。官方步骑行投屏 API 的存在不自动等于本项目获得全部使用权。未确认前，不从百度地图底图、瓦片或截图反向提取地物。

**B. 周边地物数据。** 优先审查天地图及目标城市所属地方公共地理信息平台的正式开放接口/数据集；逐项核对：可否用于外接设备自行绘制、可否在 iPhone 临时缓存、个人使用是否长期免费、是否覆盖目标城市、是否真的提供道路中心线和建筑/绿地/水域边界、坐标系与标注要求。矢量瓦片接口存在不等于地物类别齐全或授予再绘制权。取得清楚的使用依据和真实样本后才选定提供方。

如果 A 或 B 不成立，现有限制下不能承诺“全国真实道路与地物底图”。阶段交付保持真实路线与转向的圆屏显示，并明确显示“此区域无底图”；不制造假路网、不暗中改用国外数据，也不先做一套将来要丢弃的截图传输架构。继续完整底图需要取得符合条件的数据授权或调整约束。

## 固定架构与实施顺序

| 步骤 | 产物 | 通过条件 |
| --- | --- | --- |
| 3.0 基线 | 保存第二阶段提交、成功构建链接、IPA 摘要和手机测试记录；建立第三阶段分支 | 随时可安装回第二阶段版本；后续任何 iOS/shared 修改均重新审核并更新 CI 源码树锁 |
| 3.1 数据可行性 | A/B 两项使用范围结论、目标城市真实样本、覆盖和费用表 | 至少一处实际使用区域同时拿到可用的道路与地物边界；条款和接口均允许目标用途，否则先不改地图协议 |
| 3.2 圆屏基线 | 编译当前 ESP-IDF 固件、核对板型并备份、必要时刷写；测现有 BLE 演示和真实路线 | 连接、路线、转向、距离和重连有照片/日志；真实导航不混入济南演示道路 |
| 3.3 数据适配 | 在 iPhone 新增独立的国内底图提供方适配层；解析来源元数据、转换为统一 GCJ-02 场景、按可见区域裁剪和简化；只做许可允许的本机缓存 | 路线与道路坐标对齐；无数据时明确空底图；缓存断网行为符合授权范围 |
| 3.4 协议与绘图 | 保留 `MapScene 0x14` 的道路/建筑轮廓兼容性；根据真实样本和带宽测试定义带能力协商的新场景版本或增量消息，承载建筑、绿地和水域面；扩展既有 LVGL 地图图层 | 旧固件能按现有协议工作；新固件能按“地物面→道路→高亮路线→车标/指令”绘制，不改变现有圆盘布局 |
| 3.5 实机回归 | iPhone IPA、固件二进制、校验值、BLE/功耗/画面记录及更新后的安装说明 | 在实际区域测试三种路线模式、偏航、锁屏、断线重连、网络切换和缺图区域；没有错误道路、导航误导或明显卡顿 |

现有 BLE `MapScene 0x14` 固定为 GCJ-02，最多 24 条道路/192 道路点、16 座建筑/128 建筑点，当前没有绿地或水域字段。百度 iOS SDK 已全局设置 GCJ-02。新协议预算应先用密集街区的样本量和圆屏刷新实测确定；优先保障路线与指令，背景场景可以低频刷新。地图数据源与协议之间只传中立的道路/地物类型，避免将某一家提供方的字段写进固件。
