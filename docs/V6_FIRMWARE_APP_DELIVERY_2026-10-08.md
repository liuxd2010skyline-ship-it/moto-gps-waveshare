## 18 种数据情境的实际路径

| 情境 | 当前代码选择/处理 |
|---|---|
| 完整街区 | Rich：真实地物 + 同一柔光场 + 有效路线/HUD |
| 覆盖缺口 | 保留收到的完整多边形与真实道路；缺口显示原柔光，不补方块 |
| 只有路线 | RouteOnly：原前方路线、车辆、HUD、柔光，保持比例 |
| 道路但无建筑 | RoadsOnly；不制造建筑密度 |
| 定位精度不足 | 核心沿用 50 m 可用精度门限与定位/路线匹配判断；只有可用新位置才显示有效指引 |
| 定位失效 | GpsLost：隐藏旧路线、旧距离和限速，柔光静止，英文状态与弧底轨 |
| 低速航向不稳 | 沿用 QMI/航向融合与运动插值；柔光不驱动车辆或路线 |
| 手机断连 | PhoneOffline / PhoneConnecting；立即隐藏旧指引，连接后等待当前快照 |
| 无网络、有缓存路线 | 仍可沿有效缓存导航及本地离线地物显示 |
| 重算 | Rerouting：停止旧动作；等匹配的新路线代次 |
| 近转弯 | 保留真实距离，首次跨阈值轻微响应，不放大闪烁 |
| 桥/复合路口 | 仍按真实二维路线显示；当前合同没有高度/桥层，使用安静背景，不推断不存在的层级 |
| 到达 | Arrived：终止指引与运动，显示英文到达状态 |
| 单次定位跳跃 | 沿用核心接受/匹配门限，不以背景动画修改位置；无有效几何时 InstructionOnly |
| 隧道/遮挡 | 新位置失效时走 GpsLost；不编造隧道状态或未经验证的惯性距离 |
| 无网络且偏航 | OfflineOffRoute：隐藏过期指引，要求重新连接以取新路线 |
| 连续两次近动作 | 按当前动作身份与代次切换；尚无第二动作的协议数据时只显示当前有效动作 |
| 未确认限速/重连版本失配 | 限速需显式验证旗标；几何需匹配路线身份与代次，否则隐藏底图、保留仍有效的当前动作 |

这些是有数据依据的显示规则。缺少桥层、第二动作或地物时的降级路径已实现；不把缺失数据伪装为识别结果。

## BLE 扩展与预算

- 能力位 `1 << 9`：DisplayPreferences；旧固件不接收设置，新 App 提示更新固件。
- 消息 `0x15`：payload revision `u8=1`、设置 revision `u32`、intensity/speed/travel/reduce_motion/brightness 各 `u8`，合计 10 字节；按现有分片协议在 20 字节帧下传输。
- 范围：前三项 0…100，减少动态 0/1；亮度 0 表示保留实物设置，10…100 表示修改亮度。
- 手机 450 ms 合并滑杆变化，2 s 超时，最多三次尝试；重连发送最后设置。硬件应用后回传同一设置/版本，匹配回传后才显示“圆屏已应用”；普通 ACK 不冒充应用成功。
- 默认 62/75/85；速度 0 或减少动态冻结。无有效指引、隐藏页面或定位失效时冻结。
- 固件复用 466×350 RGB565 PSRAM 缓存：326,200 字节；采样用两行 118 点 RGB 浮点缓存：2,832 字节。4 px 采样后插值再量化；不按帧申请整屏内存。
- 目标更新 2 Hz；连续三帧计算耗时超过 100 ms 时降低至 1 Hz。实机能耗、帧时和显示亮度需安装后确认，原生测试不能替代硬件测量。

## 已完成验证

### 开机动画后黑屏的加固与验证边界

用户报告旧固件存在开机动画后始终黑屏、触摸与短按 PWR 无法恢复。检查发现旧动画在 1.17 秒自行淡出为全黑，主界面于约 1.25 秒才开始构造；启动失败或显示锁/DMA 等待卡住会被这个黑色间隙掩盖。当前没有捕获故障机器的串口日志，因此不能把这一交接缺陷称为全部黑屏的唯一根因。

- 完成动画的标志保持可见，直到主界面主动替换；原生测试要求等待多秒也不会自动变黑。
- 主界面构造与初始快照应用后立即提交完整一帧，随后才启动 BLE/航向等后台服务。
- 启动时获取显示锁最多等待 3 秒；独立于显示锁的启动守护任务在 20 秒未完成时记录故障阶段，自动重启一次。RTC 标志限制重试，避免持续故障造成无限重启；不会擦除 NVS、亮度或蓝牙绑定。
- 显示任务栈明确为 12 KiB 内部 SRAM，增加绘图调用余量；记录复位原因、上次故障阶段与主任务剩余栈。
- 守护范围仅为主界面启动交接，不把导航时静止画面当作故障。实际冷启动、连续电源启动及 USB/电池两种供电的稳定性仍需新固件实机确认。
- 开机/关机画面阻止在途 BLE、IMU 和设置更新访问已经删除的主界面控件；关机同时停止柔光定时器。原生回归从正在导航的界面关机后再注入这些更新，要求画面保持稳定。
